# Apple Phase 2：Qwen 真机验收

这份清单用于完成路线图中“第三方 AI 真机端到端验证”。自动化测试只验证请求、响应、安全边界和本地数据流；真实 Keychain、照片选择、网络环境与 Qwen 凭据必须在已签名 iPhone App 中验证。

## 准备

- 使用 `codex/phase1-local-health-core` 或其后续开发分支，不直接在 `main` 上修改。
- 在 `clients/apple` 执行 `xcodegen generate`，用 Xcode 打开 `HealthMonitorAI.xcodeproj`。
- 为 App Target 选择开发团队和唯一 Bundle Identifier，在 iPhone 上安装 Debug 构建。
- 准备一个仅用于测试、可随时轮换且额度受限的 Qwen API Key。不要将 Key 写入仓库、Scheme、日志、截图或录屏。

## 基础连接

1. 打开 App 的“AI”页，添加 Qwen Provider。
2. 选择 API Key 对应的地域，确认地址是阿里云 `aliyuncs.com` 的 HTTPS 地址。
3. 填写文字模型、视觉模型和 API Key，保存后执行文字连接测试。
4. 预期：显示连接成功；401/403、429、超时或非法响应时显示可理解的明确错误，且不会切换到其他 Provider。
5. 完全退出并重开 App，再次执行连接测试。
6. 预期：Profile 仍存在，API Key 可从本机 Keychain 使用；界面、日志和本地导出中不显示明文 Key。

## 视觉与隐私

1. 执行视觉能力测试。
2. 预期：只发送 App 内存生成的测试图案，不读取照片库。
3. 在“饮食记录”中新建餐食，选择一张带定位信息的照片。
4. 预期：App 在本机缩放并重新编码图片；发送前预览显示目标域名、文字、图片和可选健康摘要范围。
5. 在预览页取消。
6. 预期：不发请求、不保存 AI 结果、不写入 Apple 健康。

## 健康摘要授权

1. 保持“共享健康摘要”关闭，发送一次文字识别。
2. 预期：预览和请求均不包含 `healthSummary`。
3. 开启独立授权并重试。
4. 预期：只发送预览列出的可用字段；睡眠字段使用“最近睡眠日分钟”，按本地时间前一日 12:00 至当日 12:00 统计，上午查询时截止当前时间。
5. 再次关闭授权。
6. 预期：后续请求立即停止发送健康摘要，不影响 HealthKit 本地功能。

## 识别、匹配与保存

1. 在本地食物目录新增一个测试食物，填写名称、别名、默认份量及每 100 克营养。
2. 发送能识别该名称或别名的餐食文字或图片。
3. 预期：展示置信度、重量范围和不确定项；结果处于“尚未保存”状态。
4. 修改确认重量并执行本地营养计算。
5. 预期：只有全部食物都精确匹配本地名称或别名时才自动计算营养；营养数字来自本地目录快照，不来自 Qwen。
6. 对包含未匹配食物的结果重试。
7. 预期：只回填名称与重量备注，要求手动填写营养，不进行模糊猜测。
8. 保存餐食并按需写入 Apple 健康。
9. 预期：用户确认前没有持久化；确认后本地记录包含目录标识、数据版本和营养快照。删除餐食时只删除本 App 对应写入的 Apple 健康样本。

## 包装与营养成分表

1. 分别准备普通餐食照片、只有营养成分表的照片，以及透明包装中同时可见营养表和食品的照片。
2. 普通餐食照片预期：不显示包装或营养表区域，继续展示食物重量范围和本地目录匹配。
3. 只有营养成分表的照片预期：先展示商品、净含量、每份信息和营养表依据；看不清的字段显示为未读清，不补为 0。
4. 透明包装照片预期：包装内食品只作为商品显示，不在“包装外的其他餐食”中重复出现。
5. 若包装旁存在另一种餐食，预期：该餐食单独显示并要求确认重量。
6. 修改“实际摄入重量”，分别验证每 100 克、每份、每包装三种标签。
7. 预期：营养值只在用户确认后由本地换算；净含量只作为默认确认值，不被静默视为实际摄入量。
8. 使用模糊、反光或被遮挡的标签重试。
9. 预期：模型返回不确定项并要求核对原图；缺少每份重量或每包装重量时禁止换算。

## 失败与降级

- 临时切断网络：识别显示网络错误，手动记录、HealthKit 同步和本地评分仍可使用。
- 使用错误 Key：显示 401/403 类鉴权错误，不泄露 Key 或完整响应体。
- 触发限流：显示 429 类错误，不静默重试到其他 Provider。
- 配置不支持图片的模型：显示视觉能力错误，文字识别和手动记录仍可用。
- 删除 Key：再次请求前明确提示缺少 API Key。
